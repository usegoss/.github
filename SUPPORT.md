# Support

This file covers every repository in the [usegoss](https://github.com/usegoss) organization.

## If you are not a Goss team member

Email <support@usegoss.com> for account, billing, or product questions. It is the fastest route and the only one that guarantees a response.

Goss does not accept outside issue reports or contributions. Please do not open issues or pull requests unless a team member asks you to.

For a security problem, do not open a public issue. Follow the [security policy](https://github.com/usegoss/.github/blob/main/SECURITY.md) or email <security@usegoss.com>.

## If you are a Goss team member

Open an issue in the repository that owns the surface where the problem lives. Use the issue forms for bugs, epics, and stories; they set the matching issue type and ask for the details needed to reproduce a problem. Create a blank issue for Task work. Use a Story or Epic instead of a Feature.

- A bug in the app, API, website, or a document belongs to the repository that ships it.
- Work that spans repositories belongs where most of the work will happen, with the other issues linked from it.
- If you are not sure which repository owns a surface, open the issue in the repository you are working in and ask there.
